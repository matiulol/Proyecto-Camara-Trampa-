## 1. Objetivo de la etapa

El objetivo de esta etapa fue construir una primera version funcional del
sistema con tres partes:

- Backend con FastAPI.
- Conexion con MongoDB usando exclusivamente la base existente Ani_cam.

La arquitectura implementada en esta etapa es:

PySide6 -> FastAPI -> MongoDB

No se implementaron funcionalidades futuras como Raspberry Pi, requests remotos,
JWT, hashing, IA, subida de archivos ni almacenamiento cloud.

## 8. Autenticacion

Endpoint implementado:

POST /api/v1/autenticacion/iniciar-sesion

Recibe:

{
  "usuario": "admin",
  "contraseña": "admin123"
}

Funcionamiento:

1. Busca un documento en la coleccion usuarios.
2. Compara usuario y contraseña en texto plano.
3. Si coincide, devuelve mensaje de exito y datos basicos del usuario.
4. Si no coincide, devuelve error 401.

Importante:

- Todavia no se utiliza JWT.
- Todavia no se utiliza hashing.
- La contraseña queda temporalmente en texto plano por tratarse de una etapa de
  demostracion escolar.

## 9. Gestion de camaras

Endpoints implementados:

GET /api/v1/camaras

Lista todas las camaras.

POST /api/v1/camaras

Crea una camara. El _id se recibe manualmente y debe tener formato similar a
camara001, camara002, camara003.

GET /api/v1/camaras/{camara_id}

Consulta una camara especifica por su _id.

PUT /api/v1/camaras/{camara_id}

Modifica nombre, ubicacion, estado y fecha_instalacion.

DELETE /api/v1/camaras/{camara_id}

Elimina una camara existente. Si no existe, devuelve 404.

No se agrego un campo identificador. El identificador interno de camaras sigue
siendo _id.

## 10. Gestion de eventos

Endpoints implementados:

GET /api/v1/eventos

Lista todos los eventos.

POST /api/v1/eventos

Crea un evento. MongoDB genera el _id automaticamente como ObjectId.

GET /api/v1/eventos/{evento_id}

Consulta un evento especifico por ObjectId.

Al crear un evento, el backend verifica que exista una camara con:

camaras._id = eventos.camara_id

Si la camara indicada no existe, se devuelve 404.
